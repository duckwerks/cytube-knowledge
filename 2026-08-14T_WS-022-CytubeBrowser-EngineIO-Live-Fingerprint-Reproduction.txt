INTERPRETATION RULES
============================================================

RESULT 1 — Browser uses polling only
------------------------------------
If the live Cytube client never attempts WebSocket, stop treating the 400 WebSocket result as a blocker. The next task becomes reproducing the browser's polling-only Socket.IO behavior.

RESULT 2 — Browser attempts WebSocket and succeeds
---------------------------------------------------
This is the highest-value result. Compare the browser's exact URL, cookies, headers, Engine.IO sequence, and Socket.IO packets against WS-020. WS-023 should reproduce the smallest difference that explains the successful upgrade.

RESULT 3 — Browser attempts WebSocket and also receives 400
------------------------------------------------------------
Then the server/browser behavior is not explained by our standalone client alone. Investigate whether the browser retries/falls back to polling and whether Cytube operates normally over polling.

RESULT 4 — Browser WebSocket request differs in path/query/version
-----------------------------------------------------------------
Use the browser's exact parameters as the basis for WS-023. Do not continue guessing variants.

RESULT 5 — Static JavaScript reveals forced polling / disabled upgrades
-----------------------------------------------------------------------
Treat this as strong evidence, but still preserve the browser Network capture as confirmation.
